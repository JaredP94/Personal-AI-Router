## Global Constraints

- Target only `JaredP94/Personal-AI-Router`; never publish to NVIDIA/upstream.
- Desktop version `0.7.0-rc.1`; release tag `v0.7.0-rc.1`; draft=true, prerelease=true, latest=false. No stable release publication, existing asset replacement, stable-feed update, or main-branch push.
- Builds must use `--publish never`, `CSC_IDENTITY_AUTO_DISCOVERY=false`, and the repository's unsigned configuration. No signing/notarization claim.
- Keep the installed PAIR application, broker/workers, user data and engines untouched. Do not run a second desktop instance, install the candidate, execute uninstall/reset scripts, or repeat live engine tests.
- Preserve preexisting `.pi/`, the old unsigned `release/0.6.0` artifacts, all earlier failure logs, and both independent real node_modules trees. Never symlink node_modules or run a dependency installation against the root checkout.
- No production/contract/dependency changes; generated release metadata and documentation only. Sign off every commit (`git commit -s`). Do not edit generated services-api documentation.
- Broad Go tests run only in the existing non-root/internal-network disposable-container isolation, never on the host. Treat skips as untested, retain every failure and stop on a red gate.

## Review Focus

1. Component compatibility: existing protocol-v2 majors must not be applied twice or reset backward. Task1 audits assignments; Task3 compares every packaged `--version` against the approved version inventory.
2. Wrong/stale payload: version, arm64 architecture, source commit, binary inventory and hashes must agree. Tasks2–3 record clean candidate SHA and inspect fresh packaged manifests/binaries.
3. Stable-feed contamination: no stable release/tag/assets may be overwritten. Task4 checks draft/prerelease flags, exact target and remote assets; stable latest release remains v0.6.0.
4. Active installed application: build/testing must not start or reap its processes. Tasks2–3 record original process ownership and avoid application launch; container topology stays isolated.
5. Distribution trust/lifecycle gaps: unsigned/not-notarized and untested install/upgrade/uninstall/multi-host/other native platforms must be explicit. Task3 inspects signature status without executing the app; Task4 carries the limitations in draft notes.
