# Inference Prefill / Decode Metrics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Surface per-job and per-node prefill/decode metrics — how many tokens were prefilled versus decoded, how long each phase took, and the resulting rates — for oMLX, Ollama, and LM Studio.

**Architecture:** Each inference proxy parses the phase values the engine already reports in its response `usage` block and attaches them to the terminal `workload:completed` / `workload:errored` event. That event is already broadcast cluster-wide by the workload-manager, so every broker in the cluster receives it; each broker folds the measurement into a per-node accumulator keyed by the serving node (`scheduledOn`) and by model, and exposes the result as a snapshot over a new JSON-RPC method and push. The desktop renders the per-job numbers on the job card and the per-node aggregates on the node card. The cluster ingress emits no workload event, so the origin proxy is the single reporter per request and no request is counted twice.

**Tech Stack:** Go 1.25 (three inference proxies, workload-manager, ui-broker, new `nvpair-shared` package), TypeScript/React/Vitest (desktop).

**Spec:** [`docs/superpowers/specs/2026-10-20-inference-metrics-design.md`](../specs/2026-10-20-inference-metrics-design.md) — read §4 (design), §5 (v1 deliverables), §8 (risks) before starting.

## Global Constraints

- Branch `feat/inference-metrics` off `main`; signed-off commits (`git commit -s`); two-line SPDX header on every new file (`node scripts/spdx-headers.mjs`).
- No new npm or Go dependencies. No new worker, no new inter-node method beyond the broker's own client-facing method, no new trust boundary.
- Go owns all counting, all filtering, all aggregation across records, and every windowed rate. The desktop never counts, filters, or aggregates; it may render a **per-record ratio of two values the service reported** (one record's tokens over that record's duration), exactly as it already renders memory usage as a percentage of the reported total. Every such ratio is **labelled with the window it covers** — a 60-second windowed rate and a lifetime ratio must never appear under the same label. No `as` casts, no `any`, no `unknown` in TypeScript signatures; `@/` imports across directories; static imports only; renderer never imports `src/electron/`.
- **Only engine-measured phase values are reported.** PAIR never estimates a phase it cannot observe: a missing phase stays missing and must never render as `0`. `totalMs` is the exception and is not a phase — it is the proxy's own wall-clock duration of the request, the same number `RequestEvent.duration_ms` already carries.
- The oMLX API key is never logged, never placed in a metric, never in an error message.
- Wire changes update the producer, every Go consumer, the desktop parser, tests and docs in the same change. `desktop/docs/services-api.md` is generated by `npm run service-contracts:write` — never hand-edited.
- `services/versions.json`: a new additive field over IPC is MINOR. Bump `omlx-proxy`, `ollama-proxy`, `lmstudio-proxy`, `nvpair-ui-broker`, `nvpair-workload-manager`, and `product` + `installer` (MINOR).
- Go tests run per component: `cd services/<component> && go test ./...`. Desktop tests: `cd desktop && npm run test:unit` (files live in `desktop/tests/modular/*.test.ts`, node environment, no DOM).
- Do not add a live-engine test to CI. `services/tests` drives a fake `httptest` engine; live oMLX checks are the manual checklist in the spec §7.

### Wire contract

**Per-job measurement** — optional fields on the workload object (workload-manager spec §6, camelCase, nullable). Present means the engine measured it.

| Field | Type | oMLX source | Ollama source | LM Studio source |
| --- | --- | --- | --- | --- |
| `prefillTokens` | int | `usage.prompt_tokens` | `prompt_eval_count` | `usage.prompt_tokens` |
| `decodeTokens` | int | `usage.completion_tokens` | `eval_count` | `usage.completion_tokens` |
| `cachedTokens` | int | `usage.prompt_tokens_details.cached_tokens` | — | — |
| `prefillMs` | int64 | `usage.prompt_eval_duration` × 1000 | `prompt_eval_duration` (ns) ÷ 1e6 | — |
| `decodeMs` | int64 | `usage.generation_duration` × 1000 | `eval_duration` (ns) ÷ 1e6 | — |
| `ttftMs` | int64 | `usage.time_to_first_token` × 1000 | — | — |
| `totalMs` | int64 | `usage.total_time` × 1000 | proxy-measured request duration | proxy-measured request duration |

**Per-node snapshot** — `metrics:get-node-metrics` result and `metrics:node-metrics` push payload (identical object).

```json
{
  "nodes": [
    {
      "nodeId": "<uuid>",
      "totals": {
        "requests": 12, "prefillTokens": 3400, "decodeTokens": 900,
        "cachedTokens": 1200, "prefillMs": 4100, "decodeMs": 5200,
        "ttftMs": 3800, "ttftRequests": 12,
        "tokenRequests": 12, "prefillRequests": 12, "decodeRequests": 12
      },
      "rates": {
        "prefillTokensPerSecond": 829.3, "decodeTokensPerSecond": 173.1,
        "meanTtftMs": 316.7
      },
      "models": [{ "model": "mlx-community/Llama-3.2-3B-Instruct-4bit", "totals": { "...": 0 } }]
    }
  ]
}
```

- `totals` are cumulative since the broker started. `rates` are computed over a 60-second window: `prefillTokensPerSecond = sum(prefill tokens) / (sum(prefill ms) / 1000)`, `decodeTokensPerSecond = sum(decode tokens) / (sum(decode ms) / 1000)`, `meanTtftMs = sum(ttft ms) / count(requests that reported a TTFT)`. A rate whose denominator is zero is `0`, never `NaN`.
- `metrics:subscribe` / `metrics:unsubscribe` answer `{"subscribed": true|false}`, matching the existing `workloads:subscribe` shape.
- The push is coalesced to at most one snapshot per second and carries the full snapshot, never a delta (relay protocol v2: snapshot-per-push).

## Review Focus

1. **A rejected request (no node available) must not create a per-node entry.** The proxy answers 502 before it creates a workload, so the accumulator never sees it. If a rejection ever reached the accumulator, per-node totals would show traffic that never ran. Tasks 2 and 6.
2. **A re-asserted terminal event must not be counted twice.** The workload-manager re-asserts each terminal workload on a heartbeat and a joining peer receives a backfill snapshot; both arrive as `workloads:upsert`. The accumulator is fed only when the workload store *accepts* the merge, and never from an inferred event (the broker's node-loss sweep synthesizes failures). Task 6 and Task 7.
3. **An engine that reports nothing must render as "not reported", not as `0 tok/s` or `0 ms`.** A measured zero (a completion with no output tokens) is different from an absent value. Tasks 2, 3, 8, 9.
4. **A remote job's measurement must survive the cluster relay.** The workload-manager re-marshals a peer's event through its own typed `Workload` struct, so a field the struct does not declare is dropped on the peer → broker path — silently and asymmetrically (the originating node still shows it). Task 5.
5. **A node whose recent window is empty must still appear, with zeroed rates and its lifetime totals intact** — "idle now" is different from "never served", and a node that never served anything must not appear as a zero row. Task 6.
